# TestOnline

Веб-квиз для класса или зала. Ведущий открывает комнату на компьютере и показывает QR-код. Участники сканируют его телефоном, пишут имя и отвечают. Отдельные приложения для Android и iPhone не нужны: игра идёт в браузере.

Нужен Node.js 22 или новее.

## Запуск

В папке проекта:

```bash
npm run setup
npm run dev
```

Сайт: http://localhost:5173

`npm run setup` ставит зависимости один раз. Дальше достаточно `npm run dev`.

## Как провести игру

1. На главной нажмите «Я ведущий». Если аккаунта ещё нет, откройте «Регистрация»: логин от 3 символов и пароль от 6. После этого откроется ваш список квизов.
2. Запустите готовый квиз «Демо: общий кругозор» или создайте свой. У каждого ведущего свой список. Квизы, которые лежали в базе до регистрации, достаются первому аккаунту.
3. На экране комнаты появится QR-код и ссылка. Телефоны должны быть в той же сети Wi‑Fi, что и компьютер. Если ведущий открыл сайт как `localhost`, код всё равно ведёт на адрес компьютера в локальной сети, например `http://192.168.0.101:5173/play/633592`.
4. Участник сканирует код, вводит имя от 2 до 20 символов и ждёт в лобби. Войти можно только до старта.
5. «Начать игру» открывает первый вопрос. Пробел или стрелка вправо на экране ведущего делают то же, что большая кнопка: «Показать ответ», затем «Дальше».
6. После последнего вопроса открывается итог. Первое место отмечено коралловым кружком.

На телефонах игрока варианты можно выбрать кнопками 1–4.

В правом верхнем углу кнопка «Светлая» / «Тёмная» меняет оформление. Выбор запоминается в этом браузере. Если тему ещё не выбирали, берётся тема системы.

## Очки

Очки считает сервер по времени прихода ответа.

- Верный и мгновенный ответ: 1000.
- Верный в конце таймера: 500.
- Между этими точками очки снижаются равномерно.
- Неверный ответ и молчание: 0.

Правильный вариант не отправляется на телефоны, пока вопрос не закрыт.

## Квиз

- Название: 2–80 символов.
- От 1 до 50 вопросов.
- Текст вопроса: 2–200 символов.
- 2–4 варианта, каждый до 80 символов. Пустые поля при сохранении отбрасываются.
- У вопроса один правильный ответ.
- Время на ответ: 10, 20, 30 или 60 секунд.
- В одной комнате до 300 участников.

В редакторе есть кнопка «Загрузить Excel». Файл `.xlsx` читается так: каждая строка — вопрос, первый столбец — текст, следующие столбцы — варианты ответа. Ячейку правильного ответа нужно залить любым цветом, кроме белого. Пустая заливка и белый цвет не считаются ответом. Если первая строка — это заголовок «Вопрос» и в ней ничего не залито, она пропускается. После загрузки у каждого вопроса 20 секунд, время можно поменять до сохранения. Кнопка «Скачать шаблон» в редакторе отдаёт файл с заголовком и двумя примерами: правильный вариант уже залит жёлтым.

На странице квизов видна сводка: сколько квизов, запусков и участников, средний балл и число игр по каждому квизу. В карточке квиза «Статистика» открывает запуски с датой и временем старта. В запуске — баллы участников и доля верных ответов. У участника отдельно показаны неправильные и правильные ответы. Игры, сыгранные до этой статистики, хранят только место и сумму баллов.

Квизы и итоги прошлых игр хранятся в `server/data/testonline.sqlite`. Если задан `POSTGRES_URL` или `DATABASE_URL`, те же таблицы создаются в Postgres — так работает боевой сервер. Живая комната существует только в памяти сервера: перезапуск стирает текущую игру, сохранённые квизы остаются. Комната живёт до 4 часов, экран итога — 30 минут.

## Настройки

Файл `server/.env` необязателен. Без него действуют значения по умолчанию.

```env
SESSION_SECRET=замените-на-длинную-случайную-строку
PORT=3001
POSTGRES_URL=postgresql://...
PG_POOL_MAX=20
MEDIA_DIR=/var/lib/testonline/media
LESSON_MAX_ATTEMPTS=1
COOKIE_SECURE=1
```

- `POSTGRES_URL` — строка подключения к Postgres. Без неё работает SQLite в `server/data`.
- `PG_POOL_MAX` — размер пула соединений к Postgres, по умолчанию 20. `PG_SSL=0` выключает TLS для локального сервера.
- `MEDIA_DIR` — папка для картинок слайдов и видео. По умолчанию `server/data/media`; картинки лежат в подпапке `files`. Папку нужно включать в резервную копию вместе с базой.
- `LESSON_MAX_ATTEMPTS` — сколько раз тестируемый может отправить тест по одному уроку, по умолчанию 1. После последней попытки урок показывает сохранённый результат, повторная отправка новую строку не создаёт.
- `COOKIE_SECURE=1` — ставить, когда сайт открыт по HTTPS.
- `TRUST_PROXY=1` — приложение стоит за Nginx и читает адрес клиента из `X-Forwarded-For`.
- `MEDIA_ACCEL=1` — отдачу картинок и видео после проверки прав передавать Nginx через `X-Accel-Redirect` (нужен `location /media-internal/`, см. `deploy/nginx/default.conf`).

## Тестируемые пакетом

На странице «Тестируемые» администратор организации может загрузить файл `.xlsx`: столбцы «Класс», «Имя», «Логин», «Пароль». Класс указывается по названию (`5а`) или вместе с параллелью (`5а · 5 класс`), если одно название есть в нескольких параллелях. Пустой пароль создаётся автоматически. После загрузки показывается таблица с логинами и паролями и кнопка «Скачать CSV» — потом пароли увидеть нельзя. Строки с ошибками пропускаются, их список показывается отдельно. За один файл — до 5000 человек.

Пароли ведущих хранятся в базе как хеш. Сессия после входа живёт в cookie 14 дней.

## Сборка для одного сервера

```bash
npm run build
npm run start --prefix server
```

Сервер отдаёт и API, и собранный сайт на порту 3001. В этом режиме открывайте http://localhost:3001, а не 5173.

## Запуск в Docker

Боевой вариант: четыре контейнера через `docker compose` — Nginx со статикой, приложение, Postgres и ежедневный бэкап.

```bash
cp .env.example .env        # заполнить SESSION_SECRET, POSTGRES_PASSWORD, SUPER_PASSWORD
docker compose up -d --build
```

Сайт открывается на порту из `HTTP_PORT` (по умолчанию 80). Логи: `docker compose logs -f app`.

Что где лежит:

| Том | Содержимое |
| --- | --- |
| `pgdata` | База Postgres |
| `media` | Картинки слайдов (`files/`) и видео уроков |
| `backups` | Дампы `pg_dump`, по одному в сутки, хранятся `BACKUP_KEEP_DAYS` дней |

Резервная копия сервера — это тома `media` и `backups`. Восстановление базы: `docker compose exec -T postgres pg_restore -U testonline -d testonline --clean < файл.dump`.

Как устроена отдача файлов: Nginx раздаёт собранный клиент и проксирует `/api` в приложение. Картинки и видео приложение не льёт само — оно проверяет вход и права, а затем отвечает заголовком `X-Accel-Redirect`, и файл с тома `media` отдаёт Nginx (`MEDIA_ACCEL=1`). Без Nginx (`MEDIA_ACCEL` не задан) приложение отдаёт файлы само.

Обновление: `git pull && docker compose up -d --build`. Если одного процесса Node перестанет хватать, увеличьте `APP_REPLICAS` в `.env` — сессии в cookie, попытки в Postgres, файлы в общем томе, поэтому экземпляры взаимозаменяемы. Исключение — живые комнаты квизов: они держат состояние в памяти и работают только при одном экземпляре.

HTTPS: положите сертификаты в `deploy/certs`, раскомментируйте блок `443` в `deploy/nginx/default.conf`, добавьте порт `443:443` и том `./deploy/certs:/etc/nginx/certs:ro` сервису `web`, поставьте `COOKIE_SECURE=1`.

## Проверки

```bash
npm test
```

Запускаются три набора тестов:

- `server/test` — правила квиза и формула очков, Excel и PowerPoint, а также весь HTTP API и Socket.io: вход, квизы, ход комнаты, админка, уроки и видео;
- `client/test` — API-клиент: каждый запрос уходит с тем же адресом, методом, заголовками и телом;
- `test/architecture.test.mjs` — слои из раздела ниже: импорты идут только сверху вниз, без циклов.

Тесты сервера работают на временной SQLite. Чтобы прогнать их же на Postgres, укажите служебную базу:

```bash
TEST_POSTGRES_URL=postgresql://postgres:пароль@localhost:5432/postgres npm test --prefix server
```

Каждый файл тестов создаёт себе отдельную базу `testonline_*`. После прогона их можно удалить.

Линтер (ESLint, настройки в `eslint.config.mjs`) проверяет сервер, клиент и тесты:

```bash
npm run lint
```

## Из чего состоит проект

| Папка | Что внутри |
| --- | --- |
| `client` | Сайт на React и Vite |
| `server` | HTTP API, Socket.io и база |
| `deploy` | Nginx и бэкап для Docker |

Код сервера и клиента разложен на слои. Модуль импортирует модули своего слоя и слоёв ниже. Обратные зависимости и циклы ловит `npm test`.

Сервер, `server/src`:

| Слой | Папка | Что внутри |
| --- | --- | --- |
| Вход | `index.js`, `app.js` | Запуск и сборка: express, HTTP-сервер, Socket.io |
| Транспорт | `transport/http`, `transport/realtime` | HTTP-маршруты, проверка входа, события Socket.io |
| Сценарии | `services` | Квизы, живые комнаты и очки, статистика, уроки, админка, импорт из Excel и PowerPoint |
| Правила | `domain` | Правила без базы и сети: формула очков, проверка квиза и урока, группы и классы |
| Данные | `repositories` | Все SQL-запросы, по файлу на таблицу. Одни и те же для SQLite и Postgres |
| Инфраструктура | `infrastructure` | Настройки из окружения, подключение к базе и схема, пароли, токен сессии, файлы уроков на диске |

Кто от кого зависит:

- `transport` → `services`, `infrastructure`;
- `services` → `repositories`, `domain`, `infrastructure` (к базе — только через репозитории);
- `repositories` → `domain`, `infrastructure`;
- `domain` и `infrastructure` не зависят от других слоёв.

Живая комната — `services/rooms/`:

- `store.js` хранит комнаты в памяти и снимок в таблице `live_rooms`, удаляет просроченные;
- `game.js` ведёт игру: вход игроков, вопросы и их таймеры, ответы и очки, итог;
- `views.js` собирает то, что видят ведущий и игрок;
- `events.js` сообщает подписчикам о каждом изменении, и `transport/realtime` рассылает его сокетам.

Остальной код импортирует комнату через `services/rooms/index.js`.

Клиент, `client/src`:

| Слой | Папка | Что внутри |
| --- | --- | --- |
| Приложение | `main.jsx`, `app` | Маршруты и защита страниц по роли |
| Страницы | `pages` | Экраны по разделам: `host`, `play`, `learn`, `admin`, `lessons`. Разметка и подтверждения, данные — из хуков `state` |
| Компоненты | `components` | Рамки страниц, графики, фигуры ответов, слайды |
| Состояние | `state` | Хуки страниц: загрузка данных, формы и действия (`state/admin`, `state/host`, вход, урок). Сессия, тема, токены и опрос комнаты |
| API-клиент | `api` | Запросы к серверу, по файлу на раздел |
| Помощники | `lib` | Роли, группы, форматирование, id |

Кто от кого зависит:

- `app` → `pages`, `components`, `state`, `lib`;
- `pages` → `components`, `state`, `lib`;
- `components` → `state`, `lib`;
- `state` → `api`, `lib`;
- `api` и `lib` не зависят от других слоёв.

Запросы к серверу (`fetch`) делает только `api`, а вызывает его только `state`. `sessionStorage` и `localStorage` трогает только `state`.

Страницы:

| Адрес | Кто видит |
| --- | --- |
| `/` | Вход по коду комнаты или переход к ведущему |
| `/host/login` | Вход ведущего |
| `/host/register` | Регистрация ведущего |
| `/host` | Обзор: сводка по всем квизам |
| `/host/quizzes` | Все квизы: запуск, статистика, правка |
| `/host/history` | История игр, сортировка по дате и названию |
| `/host/quiz/new` и `/host/quiz/:id` | Редактор |
| `/host/quiz/:id/stats` | Запуски квиза, баллы и ошибки участников |
| `/host/room/:code` | Экран ведущего: QR, вопросы, итог |
| `/play/:code` | Экран участника |

Ведущий управляет комнатой по секретному токену в `sessionStorage`, не по ссылке. Ссылку из QR можно показывать всем: в ней только код комнаты.
